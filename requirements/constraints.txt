# PyQt6/-Qt6 moved to the current line (#994, owner decision 2026-09-06).
# Rationale for the move: the previous pin 6.7.3 was kept because releases
# after it ship only manylinux_2_39_aarch64 wheels (glibc >= 2.39), which the
# then-current Raspberry Pi OS / Debian 12 "bookworm" (glibc 2.36) could not
# run. That premise expired: the official 64-bit Raspberry Pi OS build branch
# (RPi-Distro/pi-gen, branch arm64) now sets RELEASE=trixie, and Debian 13
# "trixie" ships glibc 2.41. Staying on 6.7.3 therefore no longer protected a
# current target, it only protected a legacy one.
#
# What the move closes: 6.7.3 carried at least ten Qt advisories, of which
# #762 documented three. Read directly from the CVE records: CVE-2025-10728
# (Qt SVG uncontrolled recursion, CWE-674) and CVE-2025-10729 (Qt SVG
# use-after-free, CWE-416), both affected 6.7.0-6.8.4 and 6.9.0-6.9.2, so
# both ranges end below this pin. Taken from the GitHub advisory database and
# not re-checked against a second source: CVE-2026-6210 (Qt SVG type
# confusion, HIGH) and CVE-2025-5683 (ICNS DoS in QImage) from the #762 entry,
# plus further advisories naming 6.7.3 that were tracked nowhere in this
# repository (among them CVE-2025-12385 and CVE-2025-5455, both HIGH).
# Completeness of that list is not guaranteed - a very recent, not yet
# imported advisory would not show up by this method.
#
# The use-after-free is the reason the #762 acceptance could not simply be
# renewed: that decision was explicitly premised on a "crash-only DoS"
# exposure, which does not cover memory corruption.
#
# Remaining accepted risk: CVE-2026-15037 (QDom XML injection, LOW) is fixed
# in 6.12 and therefore still present here. bgremover never builds a
# QDomDocument from untrusted input.
#
# Correction to the #762 record, measured on 2026-09-06: that comment
# described the exposure as "browsing a folder containing an attacker-supplied
# SVG". QFileIconProvider returns the theme's MIME icon and does not render
# the file's contents, and bgremover never calls QIcon(path) or QImageReader
# at all - it passes ready-made QPixmaps and routes every user-supplied byte
# through bgremover.image_loading.open_validated_image (Pillow, format
# whitelist, no SVG). The only path that reached Qt's SVG code was the
# system-installed theme icons of Qt's own file dialog, which an attacker does
# not control.
#
# Platform impact of the move: BOTH Linux architectures gain a higher glibc
# floor, because 6.7.3 shipped manylinux_2_28 on each (review PR #999).
# x86_64 goes from 2.28 to 2.34 - Debian 12, Ubuntu 22.04 and RHEL 9 stay in,
# Debian 11, Ubuntu 20.04 and RHEL 8 drop out. The aarch64 AppImage/.deb now
# require glibc >= 2.39, i.e. Raspberry Pi OS / Debian 13 "trixie" or newer;
# the .deb declares that bound so an old system refuses the install instead of
# failing at startup. The self-hosted aarch64 acceptance runner must be on
# trixie before the next release candidate is built - a bookworm runner cannot
# install these wheels (--only-binary=:all:, no sdist fallback) and its
# platform job would fail in the preflight.
#
# Note on tooling: pip-audit resolves PyPI distributions against the OSV/PyPA
# database. Qt advisories are filed against Qt, not against the PyQt6-Qt6
# distribution that vendors it, so a green dependency-audit run says nothing
# about the bundled Qt. See SECURITY.md.
