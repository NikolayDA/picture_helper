### Definition Review Result

- 🟠 **#681 and its sub-issues #687–#691 describe a TIFF package that the export does not produce.** `eufymake_writer.py` writes a folder containing `color_motif.png`/`height_map.png`/`gloss_mask.png` plus `manifest.json` — exactly as fixed in the ADR; `grep -ri tiff bgremover/eufymake_*` returns no hit. Criteria about "TIFF directories/IFDs", "page order", `SampleFormat`, `PhotometricInterpretation`, `ExtraSamples`, and `X/YResolution` therefore inspect objects that do not exist in the export result. Details, the affected criteria per sub-issue, and two resolution options: [comment on #681](https://github.com/NikolayDA/picture_helper/issues/681#issuecomment-5091039442). **#687 is not ready to start until this is resolved** — an inventory that skips the format question cements the very assumption the epic is meant to test.
- 🟡 **New finding N10 (code, not just definition): the EufyMake export carries mm/DPI nowhere.** `_write_png()` calls `image.save(path, "PNG")` without `dpi=`, so the assets have no `pHYs` chunk. Physical size and DPI live only in `manifest.json`, a BgRemover convention Studio most likely does not read. The regular image export does anchor DPI (`image_ops.save_image`, from #378). #689 can therefore validate nothing the export actually transports; the decision (write `pHYs`, document manual entry in Studio, or a different container) belongs in epic #681.
- 🟢 **Two smaller inaccuracies:** #685 asks for "the project's established artifact/**TIFF** check" — what is established is `scripts/scan_release_artifacts.py`; no TIFF check exists. The sub-issue checklist in #680 is stale: #683 is closed but still unchecked, and the later-filed #699 is missing entirely.
- ✅ **Correctly defined and confirmed against the code:** #680/#684/#685/#686 (release chain; SHA/gate preconditions currently live in the issue comments), #682 and #692–#696 (`color_ops.adjust_color`, `AdjustTab`, `Canvas.preview_color_op`/`apply_color_op`, and `Layer.locked` all exist as described), #702 (verified: `right_panel_tabs.py` defines six tab classes, "Layers" is `LayerPanel`, "Height" is `HeightMapPanel`; the wrong attribution appears in all six README variants), plus #245/#656 (purely external/operational).
- **Old baseline still stable:** **N1/N2/N4/N5/N6/N7/N8/N9**, **O1–O8**, everything completed since **2026-06-25**, and release v2.7.0 (tag/publication/all three gate stages against commit `6f103ed`) remain unchanged and done.
